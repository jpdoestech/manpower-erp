## Ordered implementation slices — only after gates

1. **Freeze contracts and dependency choice.** Approve ADR-017/strategy and provider
   configuration. Inventory all current principal/reauth/revocation callers. Pin a
   maintained JWT/crypto verifier (candidate PyJWT[crypto]) and only the necessary
   Supabase Auth client/HTTP dependency after version/license/security review.
   Do not install a database SDK merely for authentication; never write crypto.
2. **Provider-independent seam, local first.** Extract only authentication proof,
   principal resolution and reauthentication/revocation boundaries. Keep existing
   local request shapes, eight-hour absolute expiry, CSRF, password/recovery,
   lockout and ordinary/admin CLI behavior. Verify local before adding cloud.
3. **Reviewed migrations.** Add approved external links and provider-session state;
   represent external-only credentials explicitly, retain local hashes/UUID/audit
   history, provider session family/rotation generation and encrypted secret fields.
   Preserve SQLite FKs/triggers during any user-table rebuild. Clean/repeat upgrade,
   populated preservation, safe empty downgrade and populated refusal tests first.
4. **Strict verifier + provider adapter.** Implement pinned-key verification and
   bounded network behavior from strategy; validate real token claims and map only
   approved active identities. Reject unconfigured issuers, anonymous/API keys,
   disabled/unlinked users and mixed provider-session credentials. No raw bearer
   token acceptance on business routes in the first browser bridge slice.
5. **Session lifecycle.** Backend login/CSRF refresh/logout/password/recovery, durable
   per-session refresh coordination, encrypted replacement and failure handling.
   Recheck provider session and active ERP user/link on every protected request.
   Make provider/ERP partial failures explicit; no untracked background retries.
6. **Controlled account lifecycle and authorization foundations.** Extend existing
   independent requests/approvals to mapping/cloud effects with durable operation
   outcomes and protected provisioning. Keep company resolver deny-all until real
   memberships exist. Do not ship a cloud mode that silently bypasses an unsupported
   administrator/recovery proof; unsupported sensitive operations stay denied and
   cannot satisfy complete C acceptance until the reviewed path works.
7. **UI-001 integration.** Consume safe provider metadata for login labels/capabilities,
   keep /me SessionView-compatible. Add provider-appropriate password/recovery
   presentation with loading/error/relogin states. No email inferred from local
   username, no tokens in Vite/browser storage, no company/admin UI auto-unlock.
8. **Recovery/portability and evidence.** Extend backup/restore validation and
   revocation for new state; native BATs force local and remain cloud-independent.
   Both-provider tests and live disposable Supabase acceptance, docs/CI/status/ADR
   review precede completion. Stop at C; do not deploy D or transfer E.

## Rollback and stop rules

No automatic provider fallback. Bind sessions to provider+issuer configuration;
switching mode/issuer revokes incompatible sessions and requires explicit relink
review. Deploy additive schema before code; rollback must refuse to erase provider
history/credentials or reactivate old sessions. Rotate secrets/revoke cloud sessions
before reverting; retain encrypted/audit history with approved retention. Local
backup is not cloud recovery. Live cutover/release actions require separate approval.

Stop implementation until existing G1/G2 acceptance and blocking C-D decisions
are satisfied, with G3–G7 integration/configuration/test conditions verified.
This planning request is not their approval. Planning completion is independent
of implementation being blocked; do not mark CR-002C DONE.
