## Acceptance and testing strategy

- Only validated /auth/me or login responses render the shell; logout/password
  changes preserve CSRF and return to sign-in; failed logout retains account.
- No localStorage/sessionStorage credentials, fake session or simulated company
  selection. No privileged admin surface based on client identity assumptions.
- All twelve requested modules represented; unfinished modules have explicit
  labels and no fabricated totals/records. Context selector explains unavailability.
- Sidebar collapse, breadcrumbs, account/notification panels, module search,
  theme persistence, empty/error/unauthorized/loading states are usable.
- Controls have labels, help/error associations, native semantics; dialogs trap
  focus/close with Escape/restore focus; tabs support arrows/Home/End; table uses
  headers/caption and horizontal overflow. Keyboard and state tests cover these.
- Desktop/tablet CSS and browser checks: no page overflow at 1440/1024/768, usable
  collapsed rail and dark/light contrast. Automated DOM tests do not prove layout.
- Existing frontend/backend tests, formatting/lint/type/build/audits and Windows
  SQLite startup/migrations remain passing. Real PG/Compose and Windows fresh flow
  are required CI evidence. Unrun checks must remain explicitly unverified.
