## Acceptance criteria and test strategy

- Frozen lock/install, Ruff format/lint, strict mypy (app/tests/migrations),
  frontend format/lint/tsc/tests/build and both dependency audits pass.
- Configuration rejects missing/malformed/non-PostgreSQL URLs without echoing
  secrets; separate Compose credentials preserve special characters.
- SQLAlchemy sessions close/rollback on success without commit and on exception;
  explicit commits persist; lifespan disposes the pool.
- On a newly created disposable PostgreSQL DB: baseline upgrade creates only the
  Alembic version table; repeat upgrade is idempotent; metadata check is clean;
  safe downgrade to base and re-upgrade work, preserving an unrelated test row.
  Verify CLI upgrade/check/downgrade in CI too. No create_all or production writes.
- Live is 200 without DB access; ready is 200 with DB and 503 on unavailable DB;
  no sensitive details in responses or logs. Compose CI stops DB, proves live
  stays 200/ready becomes 503, restarts DB and proves readiness recovers.
- Valid UUID correlation headers propagate, invalid/duplicate IDs are replaced;
  responses/errors/logs agree and concurrent requests remain isolated.
- 404/405/422/500/503 share a documented safe error envelope; HTTP protocol headers
  (Allow, WWW-Authenticate) remain intact; validation does not echo input.
- JSON logs parse, carry bounded route/status/duration fields and never contain
  sentinel secrets in headers, paths, query strings, body or exceptions.
- P0-01 bootstrap contract/security boundary and frontend tests still pass.
- Push feature branch, passing hosted CI, PR for review, no automatic merge.
